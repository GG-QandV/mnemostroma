# Release Notes — Mnemostroma v2.6.4

> **Дата:** 2026-09-18

v2.6.4 — ключевое: **замена NER-модели** (`distilbert-ner` → `gliner_small-v2.5` INT8) плюс
**мультивекторный чанкинг** длинных текстов. Действующая `distilbert-ner` покрывала 10 языков
без русского и украинского и различала 4 типа; новая проверена на 19 языках и обслуживает
6 типов из одного набора весов.

## What's new

### NER model replacement (ключевое)

- **Модель — `gliner_small-v2.5` INT8** (`GG-QandV/gliner_small-v2.5-onnx`, Apache-2.0).
  Типы сущностей передаются в промпте, поэтому одни веса обслуживают и `person`/`organization`/
  `location`/`date`, и доменные типы Мнемостромы (`technology`, `product`).
- **Лобовое сравнение при рабочем пороге 0.5 (раунд 15):** на ru/uk новая модель находит
  в **2–2.7× больше** сущностей (ru 16/30 против 6/30, uk 12/30 против 6/30) ценой большего FP
  (в основном ORG, утекающие в `location`).
- **19 языков проверено**, минимум 23/30 (раунд 15); идеально `fr`/`de` (30/30).
- **Паритет с апстримом:** `max|Δscore| = 1.19e-07` на 20 текстах (раунды 11, 14).
- **Выбор движка из манифеста** — `ModelDefinition.engine` (`bert` | `gliner`) и `entity_types`.
  Отсутствие поля означает `bert` (старая модель): откат после переключения — одна строка
  в манифесте. Неизвестное значение — `ValueError`, без молчаливого отката.
- **Известный дефект модели:** `organization` частично размечается как `location`
  (например, ВТБ — как место). Счётчики ORG нельзя читать как истину.
- **Цена:** скачивание 270 → **336 MB** (+бандл gliner); RSS ~241 MB против ~188 MB;
  p50 NER на 512 токенах ~1.1 с против десятков миллисекунд — гейт `needs_model_ner()`
  держит модель выключенной на большинстве наблюдений.

### Multichunk indexing (E-2)

- **Токенный чанкинг** — `chunk_content()` считает границы в токенах активного эмбеддера
  (цель 384, overlap 48). Раньше текст делился по `text.split("\n\n")` без подсчёта токенов:
  длинный абзац становился одним чанком, энкодер обрезал его на 512 токенах, и остальной
  текст в память не попадал никогда. Для кода границы идут по определениям и строкам,
  для прозы — по абзацам и предложениям; фрагмент, который не влезает целиком, режется
  по словам, слово длиннее окна — по символам.
- **Мультивекторный индекс** — таблица `session_chunk_vectors`, аллокатор меток
  `allocate_chunk_label()` / `release_session_labels()`. Длинный текст кодируется по чанкам,
  каждый вектор получает свою метку; `sid_to_id` остаётся 1:1 на вектор саммари.
  Короткий текст идёт одним проходом, как раньше.
- **Лимит 32 чанка на сессию** (`MAX_CHUNKS_PER_SESSION`); попадание в лимит пишется в лог
  и в `ctx.metrics["chunk_cap_hits"]` — молчаливая потеря хвоста исключена.

### Memory correctness fixes

- **`_next_session_label`** после гидрации — `max(label) + 1`, а не `len(embeddings)`.
- **Вытеснение снимает и чанковые метки** — иначе вытесненный текст продолжает отвечать на поиск.
- **`onnx_baseline` и `footprint`** — вес моделей не считается вытесняемым (см. v2.5.4).

### Tests

- Полный прогон зелёный: **1811 passed, 25 skipped, 1 xfailed**.
- Починены 4 env-зависимых теста, блокировавших suite: live-DB диагностика переведена
  в строгий `xfail` (известный баг `sessions.content_full`), RSS-замер — на `mmap`
  вместо `bytearray` (куча переиспользовала освобождённые арены), SSE-тесты больше
  не биндят реальный порт 8764 (no-bind stand-in).
- Новые: `test_token_chunking.py`, `test_chunk_vectors.py`, `test_gliner_decode.py`,
  `test_gliner_engine.py`, `test_ner_engine_dispatch.py`.

## Upgrade notes

```bash
pip install -U "mnemostroma @ git+https://github.com/GG-QandV/mnemostroma.git@v2.6.4"
mnemostroma install-models   # докачает бандл gliner_small-v2.5 (~196 MB)
systemctl --user restart mnemostroma-daemon
```

Скачивание выросло 270 → ~336 MB. Конфиг менять не нужно.

**Откат (если понадобится):** правка `active_models.ner` в манифесте плюс возврат бандла
`distilbert-ner` и `install-models`. Код `BertNER` и движок `engine: "bert"` на месте —
это правка манифеста, а не кода.
